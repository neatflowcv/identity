# ADR 0001: main 패키지 테스트를 작성하지 않고 테스트 대상 로직을 분리

- 상태: 승인
- 날짜: 2026-08-19

## 배경/문제

`cmd/identity`의 `main` 패키지는 애플리케이션을 조합하고 HTTP 서버를 시작하는
실행 진입점이다. 이 패키지에 단위 테스트를 추가하면 실행 파일 조합, 의존성
구성, 서버 시작 방식과 테스트가 결합된다. 반면 환경변수 해석이나 시작 값
검증처럼 독립적으로 검증할 가치가 있는 로직은 실행 진입점에 둘 필요가 없다.

따라서 테스트 필요 여부를 먼저 판단하고, 테스트할 가치가 있는 로직은 실행
진입점에서 별도 패키지로 분리한 뒤 그 패키지의 계약을 테스트한다. 이 원칙이
없으면 `main` 패키지에 테스트를 붙이거나, 테스트가 필요한 로직을 실행 코드에
남겨 테스트하지 않는 선택을 하게 된다.

## 결정

이 프로젝트에서는 `main` 패키지를 위한 테스트를 작성하지 않는다. 대신 테스트할
가치가 있는 로직은 `cmd/identity`에서 독립적인 패키지로 분리하고, 분리된 패키지의
공개 계약을 테스트한다.

현재 설정 로딩과 검증 로직은 `internal/pkg/config`로 분리했다. `cmd/identity/main.go`는
`config.Load(os.Getenv)`를 사용해 설정을 받아 애플리케이션을 조합하고, 설정 자체의
동작은 `internal/pkg/config/config_test.go`에서 검증한다.

## 테스트하는 것

`internal/pkg/config`의 `Load`와 그 결과인 `Config`를 테스트한다. 테스트 범위는
다음과 같다.

- 환경변수 매핑
- 포트 기본값과 유효성 검증
- 필수 값 검증
- JWT 키 길이 검증
- 각 잘못된 설정에 대한 오류 의미

이 테스트는 설정 로딩 계약만 검증하며, `main` 패키지나 실행 서버를 시작하지
않는다.

## 테스트하지 않는 것

- `cmd/identity/main.go`와 `main` 패키지의 실행 조합 및 서버 시작
- `cmd/identity`의 HTTP 핸들러와 라우터 동작

이에 따라 기존 `cmd/identity/main_test.go`와 `cmd/identity/handler_test.go`는
삭제했다. 이는 테스트를 무조건 생략한다는 의미가 아니라, 현재 해당 코드가
실행 진입점과 HTTP 연결을 조합하는 역할이므로 main 패키지 테스트를 작성하지
않는다는 결정에 따른 것이다. 이후 독립적으로 테스트할 가치가 있는 로직이
발견되면 먼저 별도 패키지로 분리한 다음 그 패키지를 테스트한다.

## 결과/후속 사항

설정 규칙은 실행 파일 조합과 분리되어 `internal/pkg/config`의 명시적인 계약으로
검증된다. `main` 패키지는 애플리케이션 조합에 집중하고, 설정 변경은 config 패키지
테스트로 검증한다.

애플리케이션 조합이나 HTTP 연결 구성을 변경할 때에는 `main` 패키지 단위 테스트를
추가하지 않고 빌드, 정적 검사 및 필요한 통합 수준의 검증을 수행한다. 새로운
테스트 대상 로직을 추가할 때는 테스트 가능성을 검토한 뒤 적절한 별도 패키지로
분리하는 것을 후속 원칙으로 삼는다.
